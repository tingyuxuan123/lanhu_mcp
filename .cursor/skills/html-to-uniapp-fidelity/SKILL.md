# HTML 严格还原为 UniApp

将源 HTML 视为唯一设计事实来源。目标是确定性转译，不是按视觉印象重新设计页面。

## 事实来源与优先级

按以下顺序读取设计事实：

1. 内联 `style`
2. CSS 选择器与 CSS 变量
3. DOM 层级、类名与资源路径
4. 源 HTML 画板尺寸

没有源值时，先说明缺失；不要补充“常见”“更美观”或框架默认值。

## 开始前：提取样式事实

在编码前，先建立简短的样式事实清单：

- 画板宽高与单位换算基准。
- 每个可见文本的内容、源节点、字号、字体、字重、行高、字间距、颜色、对齐和换行规则。
- 非白色背景、边框、圆角、阴影与透明度。
- 图片或图标的源节点和本地资源路径。
- 绝对定位元素的 `left`、`top`、`width`、`height` 与 `z-index`。
- 小程序不支持、需要降级的 CSS 特性。

这份清单是实现和验收的基准；不要跳过。

## 强制转译规则

### 尺寸和单位

- 若源 HTML 的画板宽度为 `750px`，所有设计坐标、宽高、间距、字号、行高和字间距均将 `Npx` 转为 `Nrpx`。
- `1px` 物理细边框可保留为 `1px`。
- 百分比、`vw`、`vh`、`calc()`、颜色值和透明度保持原语义；不得作猜测性换算。
- 不要无依据地限制最大宽度、增加安全边距，或修改原始画板高度。

### 排版

每个可见文本必须忠实保留源节点的：

- `font-size`
- `font-family`
- `font-weight`
- `font-style`
- `line-height`
- `letter-spacing`
- `color`，包括 `rgba()` 的 alpha 值
- `text-align`
- `white-space`、换行和省略行为

禁止使用 UI 库、浏览器或小程序的默认字号、默认颜色替代源值。

### 颜色与视觉样式

- 背景、文字、边框、阴影和透明度必须使用源 CSS 的原始值。
- 不得将原值换成“相近颜色”、主题色或设计系统默认 token。
- 可提取 token，但 token 值必须与源值严格相同，并保留从源选择器到 token 的映射。
- 不得为了简洁删除圆角、阴影、裁剪或叠层效果。

### 布局和层级

- 源节点使用 `position: absolute` 时，UniApp 必须保留绝对定位，以及对应的坐标、尺寸和 `z-index`。
- 源节点本身为 flex 或流式布局时，才使用对应的 `flex` 或普通文档流。
- 不得仅为“代码更简洁”把绝对定位设计改造成流式布局。
- 保留 DOM 的绘制顺序和层叠关系。

### 图片与资源

- 使用输入中提供的本地资源路径。
- 不重新请求蓝湖、远程图片或第三方图标。
- 不自行生成替代图标；资源缺失时明确报告缺失项。

## 兼容性降级

仅当微信小程序不支持源 CSS 特性时才允许降级。每项降级必须：

1. 在代码注释中写出原始 CSS 和降级原因。
2. 优先保持尺寸、位置、颜色和层级。
3. 在交付说明中逐条列出。

禁止静默替换为近似效果。

## 实现与审计流程

1. 读取完整 HTML、样式和本地资源目录。
2. 输出样式事实清单。
3. 生成符合项目约定的 `.vue`、样式及必要资源引用。
4. 反向审计生成代码：
   - 每一个文本节点都能回溯至源 HTML 的字号、颜色、字重、行高和字间距。
   - 每一个非默认颜色、尺寸、间距和定位值都能回溯至源 HTML。
   - 代码中不出现无来源的颜色、字号、间距或装饰值。
   - 所有本地资源路径存在且可访问。
5. 若项目具备截图或对比能力，渲染并对比；只针对有证据的差异修改。

## 交付格式

完成后只简要说明：

- 创建或修改的页面文件。
- 使用的本地资源。
- 关键的“源 HTML → UniApp”样式映射。
- 兼容性降级项；没有时明确写“无降级项”。

不得声称“像素级完成”，除非已经执行了渲染对比或能给出等价的可复现验证证据。
